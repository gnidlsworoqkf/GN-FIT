신뢰도 계산 공식
각 쌍(q, m, rev)에 대해:
  rev = false (정방향, 9쌍) → Q[q] === Q[m] 이면 +1점
  rev = true  (역방향, 10쌍) → Q[q] !== Q[m] 이면 +1점
→ 최대 19점

판정 기준:
15점 이상 → 매우 신뢰 (High) — 초록
10~14점 → 양호 수준 (Mid) — 노랑
9점 이하 → 신뢰 불량 (Low) — 빨강
admin.html과 report_v4.html이 완전히 동일한 19쌍·기준으로 계산하도록 통일되어 있습니다. 이 계산은 PART1 원본 응답(Q1~79)만으로 이루어지며 정답 개념이 없어 클라이언트에서 계산해도 노출 위험이 없습니다 — ④·⑤에서 다루는 PART2 정답키 노출 문제와는 별개입니다.

③ PART2(실제행동) 점수는 어떻게 0~100%로 환산되나
PART2(Q81~100 최고/최저 선택)의 원점수는 문항 수에 따라 0 ~ +max2 범위를 가집니다(오답 감점 없이 Best/Worst 일치分만 가산하는 방식으로 ④에서 재설계됨). 이걸 0~100% 백분율로 정규화해야 "조직 행동 성향 분류", "직무 적합도", "응답 패턴 테이블"에 쓸 수 있습니다.
p2Pct = (7 × 원점수 + 13 × 최대점수) ÷ (최대점수 × 20) × 100  →  0~100 클램핑

  → 원점수 0(중립 응답) 대입 시: (13×최대)÷(최대×20)×100 = 65%
  → 원점수 = 최대점수(만점) 대입 시: 100%
왜 50%가 아니라 65%인가: 처음에는 중립 응답=50%로 정규화했으나(오프셋 = 최대점수), 실제 응시 데이터를 모아보니 총점이 대체로 낮게 몰려서(33~60점대) 4단계 유형(보완/잠재/성장/주도형)의 판별력이 떨어진다는 문제가 확인됐습니다. 오프셋을 최대점수의 13/7배로 올려 중립 기준선을 65%로 재조정했고, 그 결과 같은 표본에서 총점 분포가 53~72점대로 넓어져 판별력이 개선되었습니다. 실제 지원자 데이터가 쌓이면 이 기준선은 다시 조정이 필요할 수 있습니다.
calcData()(report_v4.html), calc()(admin.html), computePart2Score()(google_apps_script.js) 세 곳 모두 동일한 공식을 사용합니다. 실제 계산은 이제 서버(Apps Script)에서 한 번만 이루어지고, 클라이언트는 그 결과를 그대로 표시합니다 — 자세한 내용은 ⑤ 참고.
④ PART2 정답키는 어떻게 정해졌고, 왜 두 번 다시 설계했나 신규

⑥ 문항은 어떤 순서로 나오고, 시간 제한은 어떻게 작동하나 신규
PART1(Q1~60) 문항 순서 — 응시자마다 무작위 배치
기존에는 Q1~60이 역량별로 10문항씩(주도적 능력 Q1~10, 문제해결 Q11~20 …) 순서대로 6페이지에 나왔습니다. 페이지 하나가 통째로 같은 역량이다 보니, 응시자가 패턴을 눈치채고 페이지 단위로 편향되거나 일관되게(예: 계속 A만) 답하기 쉬운 구조였습니다. 지금은 Q1~60을 응시자마다 무작위로 섞은 뒤 6페이지(10문항씩)에 나눠 배치합니다. Q61~80(거울 문항)은 배치 설계상 원본 문항과 거리를 둬야 하므로 셔플 대상에서 제외하고 기존 순서를 유지합니다. 문항 ID와 카테고리 매핑 자체는 그대로라 채점(어차피 PART1은 미채점)이나 리포트 집계 로직에는 영향이 없습니다.
PART2(Q81~100) 선택지 표시 순서 — 응시자마다 무작위 배치
④ 참고 — 정답 위치 편향(Best 2번 65%, Worst 4번 55%)을 근본적으로 무력화하기 위해, 각 시나리오 문항의 선택지 4개가 화면에 나오는 순서도 응시자마다 무작위로 재배치됩니다.
문항 페이지 제한 시간 + 뒤로가기 금지
구간페이지당 제한 시간0초 도달 시뒤로가기
PART1 문항 페이지 (8개 중 6개, 10문항씩)60초완료 여부 무관하게 강제로 다음 페이지 이동전체 검사 구간에서 완전히 제거됨 (이전 페이지로 돌아갈 수 없음)
PART2 문항 페이지 (4개, 5문항씩)120초완료 여부 무관하게 강제로 다음 페이지 이동 (마지막 페이지는 그대로 대기)
PART2는 시나리오 읽기 + 선택지 4개 검토 + Best/Worst 2회 판단이 필요해 PART1보다 텍스트량·판단 횟수가 많으므로, 문항당 평균 시간을 PART1(6초/문항)보다 넉넉한 24초/문항 수준(120초/5문항)으로 설정했습니다. 각 페이지 진입 시 카운트다운이 초기화되며, 남은 시간은 화면 상단에 "남은 시간 MM:SS"로 표시되고 10초 이하일 때는 경고색으로 깜빡입니다.
삭제된 기능 — 전체 소요시간(총) 표시
검사 시작부터 제출까지 걸린 전체 시간을 "소요 시간 MM:SS"로 보여주던 기능이 있었으나, localStorage에 저장된 시작 시각이 세션 재사용·직접 URL 접근 등으로 꼬이면서 "소요 시간 5724:59" 같은 비정상 값이 표시되는 문제가 발견되어 기능 자체를 완전히 제거했습니다(화면 표시, 추적 로직, 제출 데이터의 "소요시간(초)" 필드 모두 삭제). 문항 페이지별 카운트다운(남은 시간)은 이 기능과 별개로 계속 정상 작동합니다.

참고: 종합 유형(보완/잠재/성장/주도형)과 조직 행동 성향(실행주도/관계조율/분석신중/안정실행)은 둘 다 PART2(SJT) 점수 기반이지만 계산 범위가 다릅니다 — 종합 유형은 6개 역량 PART2 점수의 평균(총점)을, 행동 성향은 역량별 PART2 점수의 개별 임계값(55%/60%) 분기를 봅니다. 같은 총점이라도 역량별 편차에 따라 다른 행동 성향이 나올 수 있습니다. 이 분기 로직은 정답키와 무관해 지금도 클라이언트(report_v4.html)에서 계산합니다.
스펙트럼 바 위치 계산
Q1~Q60 중 A 응답 개수 ÷ 전체 응답 개수 × 100 = A비율(%)
마커 위치 = 100 - A비율

예시: A를 60%로 선택했다면 → 마커는 40% 위치 (왼쪽, 절차·안정형 쪽)
⑧ 직무 적합도 추천은 어떻게 계산되나
굿네이버스 「역량가이드북」에 정의된 4개 핵심직무(국내사업/국제사업/마케팅/회원관리)의 실제 핵심역량을 기준으로, 기존 6개 검사 역량 점수(종합 유형과 같은 PART2 전용 점수)를 직무별 가중치로 재조합합니다. 전용 문항을 새로 만들지 않고 기존 점수를 재활용하는 방식이라 응시 시간이 늘어나지 않습니다.
직무가이드북 핵심역량 3가지매칭한 검사 6역량 가중치
국내사업 사업기획및추진력 · 체계적업무관리능력 · 효과적커뮤니케이션능력 목표달성능력 35% + 문제해결능력 30% + 의사소통능력 35%
국제사업 사업기획력 · 프로젝트관리능력 · 영향력과설득력 목표달성능력 35% + 문제해결능력 35% + 소속내영향력 30%
마케팅 통합적사고력 · 컨텐츠기획력 · 데이터기반의사결정능력 목표달성능력 33% + 주도적능력 34% + 문제해결능력 33%
회원관리 서비스기획력 · 정확한업무처리능력 · 디지털활용능력 의사소통능력 35% + 조직문화형성능력 35% + 문제해결능력 30%
직무 점수 = Σ (해당 직무 가중치 × 매칭 역량의 총점)  →  4개 직무 점수를 원점수 기준으로 비교해 순위 결정 → 순위 확정 후에만 반올림
동점 처리 주의: 4개 직무 점수가 반올림하면 같아 보여도 원점수는 미세하게 다를 수 있습니다. admin.html과 report_v4.html 모두 반올림 전 원점수로 비교 → 승자 확정 후 반올림하는 방식으로 통일해, 근소한 차이의 응시자에게 서로 다른 직무를 추천하던 버그를 해결했습니다. 이 계산 자체는 역량 점수(이미 서버에서 계산된 값)만 사용하므로 정답키 없이도 클라이언트에서 그대로 계산합니다.
화면 표현 방식 — 점수 숫자는 표시하지 않음
처음에는 "76점" 같은 숫자를 함께 보여줬으나, 총점(0~100점 만점, 예: 69점)과 나란히 보이면 같은 척도로 오해하기 쉽다는 문제가 있었습니다 (직무 적합도 점수는 6개 역량 중 3개만 가중합한 값이라 총점과 척도 자체가 다름). 그래서 숫자를 없애고 순위(①②③④) + 막대 길이(상대 비교) + 1위 항목의 "가장 적합" 태그로만 표현하도록 변경했습니다.

총점유형 배지 + 조직 행동 성향 배지 + 🎯 추천직무 배지. 총점 구간별 자동 생성 종합 의견 텍스트, 전체 평균 대비 ±점수 함께 표시.
조직 행동 성향 + 스펙트럼 바
4가지 유형 중 하나 + 설명 + 장단점. 하단에 절차·안정형 ↔ 주도·혁신형 그라디언트 바에 마커 위치 표시.
물결 실루엣 + 6각형 레이더 차트
왼쪽: 총점만큼 물이 차오르는 실루엣 + 상위% 텍스트. 오른쪽: 6각형에 역량명과 점수 라벨 직접 표기. 6개 축 모두 서버에서 계산된 PART2 점수 기준.
우수/보완 역량 카드 + 채용 추천
순위는 PART2 점수 기준 상위 2개/하위 2개. 설명 문구는 PART1 성향 방향(A/B)에 따라 서술(예: A 우세면 "지시 대기 경향..." 문구). 하단에 총점·신뢰도·Fake-Good 기반 3단계 채용 추천 카드.

PAGE 3 가치관·행동 비교 + 심층 분석 + 신뢰도
가치관(PART1) vs 실제행동(PART2) 비교
6개 역량 각각 P1%·P2%를 두 줄 막대로 표시. 갭 20점 이상만 빨간 바 + ⚠ 경고. P1%는 이 섹션 전용의 A=10/B=7 가중치 계산을 그대로 유지하고, P2%는 서버가 계산한 역량 점수를 그대로 재사용합니다(더 이상 ANSWER_KEY로 직접 재계산하지 않음).
핵심 문항 심층 분석
Q9·Q12·Q25·Q34·Q45·Q56 응답 체크. 이상 없으면 ✔, 경고는 ⚠, 위험은 🚨. 6개 역량 전부 2열 그리드로 표시.
응답 신뢰도 검증
신뢰도 점수(19점 만점) + 역량별 거울 문항 일치율 막대(역방향 쌍 반영) + Fake-Good 배지(Q80 B선택 또는 서버가 계산한 fakingGood 플래그).

신뢰도 총점과 역량별 일치율 모두 동일한 19쌍 MIRROR_PAIRS(rev 플래그 포함) 기반으로 계산됩니다. admin.html과 report_v4.html이 완전히 같은 배열과 판정 규칙을 공유하므로, 두 화면에서 같은 응시자의 신뢰도가 항상 일치합니다. 이 계산은 PART1 원본 응답만 사용해 정답 개념이 없으므로 클라이언트에서 계산해도 노출 위험이 없습니다.
